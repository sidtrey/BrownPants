# BrownPants 0.3.0

BrownPants 0.3.0 expands source-grounded brownfield impact analysis and makes its limits and measured results easier to review. It adds substantial capability without adding package dependencies.

## Highlights

- Trace managed impact through generic and implicit constructors, nested callables, method-group delegates, and supported C++/CLI bridge candidates.
- Follow supported MFC message-map dispatch and explicitly qualified native calls while keeping native results labeled as lexical candidates.
- Find WinForms control-property writes that may need UI-thread review, including split and derived control types.
- Group repeated architecture and framework evidence without discarding the individual source locations; preserve precise columns for multiple findings on one line.
- Improve compiler-diagnostic summaries and show when unresolved delegate targets make impact incomplete.
- Add measured, source-audited examples and a local SDD review-workbench screenshot to the README.

## What the comparisons show

In the frozen local-delegate persistence task, three matched Codex pairs improved actionable impact recall from 50% to 100%, with precision unchanged at 100%. All three pairs favored BrownPants, and all six repairs passed the same independent regression check. This is evidence for that delegate scenario and recorded host/model setup, not a general performance claim.

The broader Brownfield Bug Lab comparison did not meet its pre-registered quality threshold: recall moved from 25% to 30%, while precision fell from 71.4% to 66.7%. Both conditions made the same repair and passed the independent check. The README and detailed reports preserve both outcomes.

## Install

Download `BrownPants.Cli.0.3.0.nupkg` from this GitHub release and install it from the directory containing the package:

```powershell
dotnet tool install --global --add-source ./release BrownPants.Cli --version 0.3.0
brownpants inspect .
```

The package has no new runtime dependencies compared with 0.2.1. Semantic MSBuild analysis may evaluate imported project targets; inspect trusted repositories before enabling `--semantic`.
